3) اصلاح قطعی قابل پیشنهاد: Fail-closed برای دانلود مدل زبانی
======================================================================

فایل:
app/src/main/java/com/example/sol/knowledge/ModelCatalog.kt

وضعیت مشاهده‌شده:
مقادیر زیر هنوز Placeholder هستند:
QWEN3_0_6B_INT4_SHA256 = "TODO(verify)"
QWEN3_0_6B_INT4_BYTES = -1L
QWEN3_0_6B_INT8_SHA256 = "TODO(verify)"
QWEN3_0_6B_INT8_BYTES = -1L
QWEN2_5_1_5B_Q8_SHA256 = "TODO(verify)"
QWEN2_5_1_5B_Q8_BYTES = -1L

در ModelDownloader.downloadModel مسیر asynchronous فعلی این آرگومان را ارسال می‌کند:
allowHttpsWithoutPinnedHash = true

این یعنی مسیر دانلود عادی می‌تواند از مسیر دانلود رسمی HTTPS با متادیتای دریافتی هنگام درخواست استفاده کند؛ این با Hash از پیش تأییدشده و ثبت‌شده در برنامه یکسان نیست.

Patch پیشنهادی حداقلی:
در ModelDownloader.kt، فراخوانی downloadModelSync را از:

downloadModelSync(
    spec = spec,
    onSavedPath = onSavedPath,
    allowHttpsWithoutPinnedHash = true,
)

به این تبدیل کنید:

downloadModelSync(
    spec = spec,
    onSavedPath = onSavedPath,
)

نتیجه مورد انتظار:
- چون مقدار پیش‌فرض allowHttpsWithoutPinnedHash برابر false است، مدل فاقد Hash معتبر رد می‌شود.
- دانلود تا زمان ثبت Hash و اندازه دقیق تأییدشده فعال نخواهد شد.
- این رفتار Fail-closed است و برای امنیت بهتر است؛ اما قبل از انتشار باید Hash و اندازه واقعی هر مدل از متادیتای رسمی و قابل اعتماد ناشر استخراج و مستقل تأیید شود.
- از وارد کردن Hash ساختگی یا Hash گرفته‌شده از همان فایل دانلودی به‌عنوان «تأیید مستقل» خودداری شود.

توجه:
تابع downloadOfficialSlmWithFallback و مسیر import مدل محلی باید جداگانه بازبینی شوند. فایل واردشده از کاربر باید حداقل از نظر فرمت، اندازه، نوع مدل و Hash ثبت‌شده/تأییدشده کنترل شود. Hash محاسبه‌شده صرفاً برای شناسایی فایل، اصالت ناشر را ثابت نمی‌کند.

تست‌های لازم:

این مسیر می‌تواند بررسی Hash رسمی را دور بزند؛ در حالی که initialize به‌صورت پیش‌فرض verifyOfficialHash=true دارد.

Patch پیشنهادی:
این بخش به شکل زیر تغییر کند:

if (!isReady && isModelPresent) {
    if (!initialize(verifyOfficialHash = true)) return null
}

شرط اعمال:
این تغییر فقط وقتی درست است که مدل رسمی با EXPECTED_CAMPP_SHA256 استفاده شود.
اگر Import مدل شخصی/سفارشی مجاز است، باید مسیر جداگانه‌ای با تأیید کاربر، Hash ثبت‌شده در زمان Import، تشخیص معماری مدل و برچسب «مدل تأییدنشده ناشر» طراحی شود. مدل سفارشی نباید بی‌صدا به‌عنوان مدل رسمی تلقی شود.

مواردی که هنوز نیازمند تست هستند:
- نام و تعداد ورودی‌های ONNX.
- Shape ورودی واقعی مدل CAM++.
- نوع ورودی: waveform یا Fbank.
- ترتیب ابعاد Tensor.
- نرخ نمونه‌برداری 16kHz.
- تعداد Mel binها و پارامترهای پنجره/FFT.
- نوع خروجی و نرمال‌سازی embedding.
- تطبیق خروجی اندروید با مرجع معتبر مدل.

نکته مهم:
صرف اجرای موفق ONNX Runtime اثبات صحت Speaker Embedding نیست.
تا قبل از ارزیابی FAR/FRR و آزمون replay، Speaker ID فقط باید یک سیگنال کمکی باشد، نه عامل مجوز عملیات حساس.

طرح API پیشنهادی (اسکلت معماری؛ قبل از کدنویسی نهایی باید با DI و کلاس‌های موجود تطبیق داده شود):

enum class SolModelKind {
    VOSK_ASR,
    PIPER_TTS,
    SPEAKER_ID,
    LOCAL_SLM
}

sealed interface ModelAcquireResult {
    data object Acquired : ModelAcquireResult
    data class InsufficientMemory(
        val availableMb: Long,
        val requiredMb: Long
    ) : ModelAcquireResult
    data class Busy(
        val activeModel: SolModelKind
    ) : ModelAcquireResult
    data class Failed(
        val reason: String
    ) : ModelAcquireResult
}

interface SolModelResource {
    val kind: SolModelKind
    suspend fun load(): Result<Unit>
    suspend fun unload()
    fun isLoaded(): Boolean
}

1. برای ASR و TTS در حالت عادی اجرای ترتیبی ترجیح داده شود.
2. Speaker ID فقط در صورت فعال بودن تنظیم و وجود حافظه کافی بارگذاری شود.
3. SLM در صورت کمبود حافظه غیرفعال بماند و پاسخ NLU سبک ارائه شود.
4. هیچ مدل سنگینی در onCreate یا شروع سرد برنامه به‌صورت اجباری بارگذاری نشود.
5. هنگام onTrimMemory، وضعیت مدل‌ها ارزیابی و منابع غیرضروری آزاد شوند.
6. مدل در زمان اجرای inference آزاد نشود.
7. آزادسازی باید idempotent باشد؛ چند بار صدا زدن unload باعث Crash نشود.

6) سیاست Offline Strict
======================================================================

در PRIVACY.md توضیح داده شده که Android SpeechRecognizer یا صدای TTS سیستمی ممکن است وابسته به سرویس آنلاین باشد.

پیشنهاد:
یک تنظیم روشن و قابل مشاهده اضافه شود:
Offline Strict (پیش‌فرض پیشنهادی برای این محصول)

رفتار:
- ASR فقط از Vosk محلی استفاده کند.
- اگر مدل Vosk نصب نیست، به‌جای SpeechRecognizer سیستم پیام روشن نمایش داده شود.
- جست‌وجوی وب و دریافت URL در این حالت غیرفعال باشد.
- دانلود مدل فقط با خاموش کردن موقت Offline Strict و تأیید صریح کاربر انجام شود.
- TTS ابری/سیستمی در حالت Strict استفاده نشود؛ فقط موتور محلی تأییدشده یا متن.
- وضعیت اتصال شبکه و آخرین درخواست شبکه در صفحه حریم خصوصی قابل مشاهده باشد.

اسکلت تصمیم‌گیری پیشنهادی:

enum class SolNetworkPolicy {
    OFFLINE_STRICT,
    USER_APPROVED_NETWORK
}

fun canUseNetwork(
    policy: SolNetworkPolicy,
    userConfirmedThisAction: Boolean
): Boolean {
    return policy == SolNetworkPolicy.USER_APPROVED_NETWORK &&
        userConfirmedThisAction
}

این تابع به‌تنهایی کافی نیست؛ تمام نقاط شبکه (وب، دانلود مدل، دریافت کتاب، APIهای جانبی) باید از یک لایه سیاست واحد عبور کنند. تست باید ثابت کند در Offline Strict هیچ درخواست شبکه‌ای آغاز نمی‌شود.
